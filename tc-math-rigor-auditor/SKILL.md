# 數學嚴謹性審查（繁體中文原稿）

目標是辨認會改變數學意義或誤導讀者的問題，提出足以修復問題的最小修改。使用繁體中文回報。審查要求本身只授權閱讀、驗證與產生報告；若使用者已要求修訂，則依其授權實作，不再重複索取同一授權。

## 範圍與基準

- 讀取專案自己的約定文件（如有）與適用的章節約定。本 skill 只審 TC；翻譯前審查以 TC 原稿為準。既有 EN 版僅作對照，不能反過來替 TC 補足未寫出的假設。
- 確認目標檔、來源 commit、工作區是否有修改，並記錄實際讀取檔案的 SHA-256。使用工作區現有內容，不覆蓋既有修改。只審部分小節時明列範圍，不宣稱全章通過。
- 先通讀整章，建立定義、符號、全域假設及引用索引，再逐節檢查。使用本 skill 的 `scripts/nb_extract.py` 抽取 notebook source（可用 `--range` 分段），或以標準庫 json 讀取；cell 索引為 0-based，cell 內行號為 1-based。大型輸出分段讀至完整，不能把被截斷的輸出視為已讀。
- 檢查可疑缺漏前，回查前文與相關引用。章首明確宣告的假設可以沿用；後章才補上的假設不能自動修補本章的無條件斷言。未取得引用來源時標明未驗證。
- 以完整定義、定理與證明或完整小節為審查單位，不按固定 cell 數切斷論證。

## 判讀約定（TC）

- 行／列依 [`references/tc-conventions.md`](references/tc-conventions.md)（繁中「行 = column、列 = row」），採 0-based 索引。本 skill 只審 TC；審 SC 用 `sc-math-rigor-auditor`，不要以本 skill 審 SC。須按句意判斷，不能把「進行」「排列」「一系列空間變換」等字串計數當成術語證據。
- 內積對第二引數線性、第一引數共軛線性；`A*` 為共軛轉置。物理慣例與數學慣例不同不等於錯誤。
- 專案的翻譯術語表（如有）是既定翻譯對照，不是數學真值來源。若術語表與定義有衝突，列出證據及受影響項目，不以術語鎖否定反例。
- label 是定位資訊。格式、重複 label 或斷鏈與數學問題分開記錄；審查時不自行改動跨語言共用 label。

## 檢查重點

| 對象 | 判斷要點 |
|---|---|
| 定義與命題 | 對象、定義域與對應域、數域、維度、量詞作用域、存在與唯一性；充分／必要／充要條件有無倒置 |
| 證明 | 每步是否由已知條件推出；有無循環論證、偷用待證結論、把特例推成一般、漏掉分支 |
| 運算 | 除數非零、矩陣形狀、可逆性、正定性、實數與複數差異、有限與無限維差異 |
| 退化情形 | 零向量、空集、單元素集、奇異矩陣、線性相依、重根、零維空間；只測與命題相關的情形 |
| 幾何用語 | 面積與有向面積、向量與直線的夾角、投影的非零或子空間條件；比喻是否被當成精確定義 |
| 例題與程式 | 公式、輸入、實際計算、預期值字串與圖形是否一致；浮點誤差與容差是否影響宣稱 |
| 跨節／跨章 | 同名概念是否更換定義、前文結論是否被超出範圍使用、後續論證依賴何項缺陷 |

歷史敘事若在範圍內，將可查證事實與修辭分開；有爭議的年代、歸因及「首次／唯一」等宣稱應查原始或權威來源，不能憑模型印象裁定。

## 證據與誤報控制

每一項發現先引用精確原句及定位，再說明問題。正式列為確定錯誤，需有可核對的推導、符合原假設的反例，或直接支持該判斷的可靠來源。反例要代回原敘述，說明哪個結論不成立。

分別記錄問題類型、影響程度與判斷確定度：

- 類型：`mathematical_error`、`missing_condition`、`ambiguity`、`pedagogical_simplification`、`style_preference`、`factual_claim`、`structural_issue`。
- 影響：`high`（核心結論或後續論證受影響）、`medium`（局部適用範圍或解讀受影響）、`low`（局部表達或排版）。
- 判斷：`confirmed`、`needs_verification`、`dismissed`。無法證實的懷疑不得寫成已確定缺陷。

已清楚標示適用範圍且不影響結論的教學簡化不算錯誤；純風格建議另列、不得計入數學缺陷。可選擇保留重要誤報的排除理由，避免下次反覆提出。

數值驗算可找反例，不足以證明全稱命題。SymPy 等符號工具須記錄假設與適用範圍，不能把化簡成功當成所有情形的證明。執行 notebook 前先檢查副作用與依賴；優先抽出小段確定性驗證到暫存環境，避免改寫原 notebook outputs。未執行就明說未執行。

## 獨立覆核（有需要且工具可用時）

預設一位主審即可起步。核心定理、證明缺口或高影響發現適合由另一 agent 覆核；不強制安裝框架、不固定模型品牌，也不自動建立雲端任務。

給覆核者完整相關小節、全域假設、原始素材與相同來源指紋。第一輪不要透露主審結論，請其獨立推導或找反例；再核查雙方的分歧。要求覆核者只回傳發現與證據，不並行修改教材或同一報告檔。

主代理按證據整合，不用多數決。報告如實列明是否有獨立覆核；同一代理自查不稱為獨立覆核。沒有 delegation 工具時，以第二輪自查完成並記錄限制，不因此停止審查。

## 交付與後續修訂

產生報告前讀 [報告格式](references/report-format.md)。預設輸出版本化 Markdown 到專案根目錄的 `rigor_reviews/`，使用者指定的格式或位置優先；不覆蓋舊版報告、不自動修改專案的其他記錄（教學分析、翻譯進度等）。報告摘要以最高影響且有證據的項目為先。

只在使用者要求修訂時套用修正。區分確定可修事項與需要作者選擇定義或教學範圍的事項；後者提出具體選項。中文修訂後追蹤已存在的英文對應位置，依授權同步，未同步的標為待同步。不要為審查重譯整章。

改動後按風險驗證 JSON、非 source 欄位、label／引用、數學結論與受影響代碼；只有執行過的檢查才標通過。源檔指紋改變時，舊報告須標為針對舊版本，不沿用「全章已審」結論。
